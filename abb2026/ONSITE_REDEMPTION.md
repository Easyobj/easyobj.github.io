# ABB2026 现场核验与本人领取流程

规则已由用户确认：资格由现场工作人员核验，必须本人领取，核验发生在领奖前。V5.9.7 用户端新增二维码和倒计时；仍使用 PHP 模板及普通表单，不新增 JSON 业务 API、电子参会名单、手机号或身份证采集。后台微信扫一扫尚待接入，当前按下述备用码方式查询。正式部署暂不进行，Pages 仅静态预览，本地开发身份不能替代真实微信授权验收。二维码说明见 `CLAIM_QR.md`。

## 参与者

1. 本人到领奖现场，在自己的微信中打开活动中奖页，点击“兑换礼品”。
2. 点击“生成领取二维码”，现场出示二维码和倒计时；当前后台未接扫一扫时，展开“无法扫码？查看备用确认码”，供工作人员输入 12 位兑奖码和 16 位本人确认码。
3. 二维码与本人码共用两分钟有效期，只能授权对应账号和奖品的一次核销。显示 MM:SS 倒计时，刷新页面可恢复未过期凭证；点击“刷新领取二维码”后旧凭证立即失效。过期图像和备用码从弹层移除，需重新生成。每用户每分钟最多生成三次，达到上限请等冷却恢复。
4. 不接受截图或代领，不向他人转发确认码。请在领取现场生成，不要提前生成后排长队；过期时重新生成并让工作人员重新查询。
5. 已核销时只显示已领取状态，不能再次生成或重复领取。

## 工作人员

1. 使用自己的运营或仅核销账号登录后台，不共享账号。必须由现场工作人员按实际现场规则判断资格，程序不伪造主办方名单或自动判定参会身份。
2. 请参与者本人现场打开自己的微信页面并生成确认码，输入兑奖码和当前本人码，点击“查询领取信息”。静态兑奖码/旧截图本身不能授权待核销奖品的确认。
3. 对照奖品、昵称、未核销状态和风险提示，现场核验资格与本人领取。风险提示只辅助复核，不代表已证明违规，也不自动授予或取消资格。
4. 核验通过：明确勾选“已在现场核验领取资格”和“已确认本人持自己的微信页面领取”，再点击“已核对，确认核销”。两项缺一服务端都会拒绝。只有收到核销成功后才发出奖品；网络异常应重新查询状态，不凭按钮点击认定成功。
5. 核验未通过：选“资格尚未核实”或“不是本人领取”，点击“暂不核销，记录未通过”。只写工作人员、奖品及固定结论审计，不核销、不取消中奖、不回收库存。后续补验必须重新查询；不得先发奖再补记录。
6. 本人码过期/更新、工作人员确认过期、风险审核变更时，按提示重新生成或查询。仅工作人员重新查询不会延长本人码期限。
7. 已核销记录显示原核销时间，不提供再次发奖按钮；暂停新增抽奖不影响既有奖品的核验和核销。

## 技术边界与数据

- 一次兑奖记录最多核销一次，事务行锁防并发重复，成功时本人码消费、核销状态和审计必须一起提交；审计失败也不发奖。重复操作不能再次扣库存或再发奖。
- 本人码绑定微信授权账号和中奖记录，不是对自然人身份的自动认证。没有唯一人员凭证，无法严格保证一人用多个微信只领一次；领奖前核验也不能阻止多账号先抽奖占库存。
- 短期码可减少旧截图复用，但不能阻止实时转发、屏幕共享、串通或工作人员违规确认；本人核对仍依赖现场执行，不宣称仅凭持码即证明身份。
- 确认码明文仅存在本人的会话和页面；数据库存摘要，核销审计不存确认码。过期摘要可用现有 `api/bin/cleanup-security.php` 限量清理，不清理用户、中奖或核销审计；运营审计沿用既有受控保留策略，正式上线前再确认期限。
- 未获得额外批准，不自动撤销历史中奖、不释放未领取库存、不加入实名或电子凭证规则。如日后要求自然人严格去重，需补充可靠唯一资格来源，再另行设计增量迁移。
