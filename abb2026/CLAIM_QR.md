# 核销码（二码合一）与扫码停用说明（V5.9.14）

按用户要求暂时下掉二维码扫描，用户端不再展示二维码，后台不再显示扫一扫、加载扫码脚本/微信 JS-SDK 或请求扫码签名。用户在本人微信中奖页点击“生成核销码”，后台直接输入完整核销码，查询后现场核验并确认核销。

## 格式与操作

- 展示格式：`<12位大写十六进制兑奖码>-<16位大写十六进制本人确认码>`，合计 29 字符。只有一个输入框；服务端也接受 28 字符的无连字符形式及小写输入。
- 用户页面直接展示核销码和两分钟倒计时，提供复制按钮；复制权限不可用时可长按复制或直接输入，不依赖扫码权限。
- 生成/刷新仍使用原 PHP CSRF + 一次性表单凭证。核销码最多两分钟有效，且不超过奖品当天/两小时领取截止；刷新旧码立即失效，每用户每分钟最多生成三次。
- 刷新页面恢复该本人会话中未过期的核销码；到期清除展示并停用复制，重新打开不会复活旧码。
- 工作人员输入码仅查询，不自动核销；核对真实奖品和未领取状态，勾选资格及本人两项后才可确认核销。已核销奖品不能重复发放。

## 服务端与发布

二码合一不更换抽奖记录或数据库结构。拆分出的两段仍执行原有奖品归属、有效期、角色、限频、CSRF、一次性消费、行锁和审计验证。错误输入会清除该会话上一次待核销确认，避免复用旧查询结果。旧双输入表单在更新过渡期继续兼容，当前界面只提供一个输入框。

核销码包含短期本人凭证，不放入 URL、日志、localStorage 或核销审计；数据库仍仅存本人码摘要。扫码文件和库保留为历史实现，当前页面不加载、不调用。无需新 SQL，不删除现有用户、中奖、库存或 Runtime。

FTP 上传代码由 `api/bin/build-server-release.php` 白名单重建，保留原服务器配置及 Runtime。正式 PHP 业务须上传更新后的服务端代码；GitHub Pages 只发布静态预览，不执行真实核销。操作细节见 `ONSITE_REDEMPTION.md`。

V5.9.7/V5.9.10 的二维码展示和后台扫一扫已停用，历史实现可由 Git 历史恢复。
