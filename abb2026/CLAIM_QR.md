# 用户端领取二维码与工作人员扫一扫（V5.9.10）

V5.9.10 接入工作人员后台微信 JS-SDK 扫一扫：在手机微信中登录后，点击“微信扫一扫 · 核验领取二维码”，自动读取当前二维码的两段凭证，通过既有 PHP 查询表单 POST，不需要输入长码。扫码不会自动核销，仍需工作人员核对资格和本人领取并勾选确认。手输入口折叠为备用；电脑或 SDK 失败时显示明确提示。不增加 JSON 业务 API，不把领取凭证放到 URL、日志或浏览器持久存储中。

JS-SDK 配置由 PHP 模板注入，仅登录的微信后台页面生成；仅申请 scanQRCode 权限。服务端按当前 HTTP/HTTPS、二级目录与原始 query 签名，排除 hash，不信任请求 Host。稳定版令牌采用 force_refresh=false，与去年普通令牌相隔离；ticket/令牌只在今年 Application/Runtime/wechat-js-sdk 内缓存，目录0700、文件0600，PHP404 guard与排他锁保护，失败30秒冷却。客户端不获得ticket、token、secret或rawString。

真实微信验收需公众号已配置 www.abbrobotics.com.cn 的网页授权域名、JS接口安全域名和服务器出口IP白名单；工作人员必须在手机微信中打开后台。普通浏览器/自动化模拟通过不等于真机授权或摄像头已验收。官方说明：[网页授权](https://developers.weixin.qq.com/doc/service/guide/h5/auth.html)、[JS-SDK及扫一扫](https://developers.weixin.qq.com/doc/service/guide/h5/jssdk.html)、[稳定版令牌](https://developers.weixin.qq.com/doc/service/api/base/api_getstableaccesstoken)。

V5.9.9 生效规则：奖品仅限中奖当天、抽奖后两小时内现场本人领取，截止取更早者；过期库存保持锁定，不能再抽。二维码最长两分钟且不能超过奖品领取截止，刷新不延长两小时。中奖页单独显示两小时领取倒计时，扫码凭证单独显示两分钟倒计时。开始日期由 operator 后台设置，详见 `PRIZE_RULES_2026.md`。下文为 V5.9.7 功能的历史实现说明。

以下 V5.9.7 记录是用户端二维码的历史实现，后台现已接入扫一扫代码（见上方 V5.9.10），真机微信联调仍须现场确认。Pages 仅静态设计预览，不生成中奖记录或真实领取凭证。

## 实施顺序

1. 复用已有 `claim_confirmations` 两分钟、一次性、更新即失效机制，不新增数据库字段，不改公众号密钥或正式账号。
2. 在本人领取弹层中生成本地 SVG 二维码，显示 `MM:SS` 倒计时和剩余有效期进度，保留折叠的备用确认码。
3. 用 PHP 服务器时间及浏览器经过时间计算显示，避免手机时区或错误日期影响显示；后台切回、聚焦和页面恢复时立即重算，过期清除图像及备用码。
4. 验证独立解码、375/390px 页面、刷新恢复和更换凭证、到期隐藏、服务器过期/重放拒绝及人工确认门禁。
5. 同步纯 FTP 上传包及源码，推送源码 main 和 Pages master，验证线上版本后交付。测试截图、一次性测试数据库和本地配置不发布。

## 用户操作

- 本人到现场打开微信中奖页，点“兑换礼品”→“生成领取二维码”。有效期从服务器生成时开始，不从打开弹层时开始。
- 页面显示最多 `02:00` 的倒计时。刷新页面可恢复该会话的未过期凭证；关闭再打开不会延长有效期。
- “刷新领取二维码”通过原有 CSRF + 一次性表单凭证提交并更新数据库摘要，旧二维码和旧备用码立即失效。每用户每分钟最多生成三次，不无限自动刷新。
- 过期后移除图像，提示“二维码已过期”，按钮变为“重新生成领取二维码”。即使保存过截图，服务器也按数据库有效期拒绝过期凭证。
- 已领取的用户没有生成入口。人工核对资格及必须本人领取规则不变。

## 二维码约定及安全边界

二维码为固定文本，不是链接：`ABB2026:1:<12位大写十六进制兑奖码>:<16位大写十六进制本人确认码>`。不含 OpenID、昵称、身份证、密码或公众号密钥。二维码包含短期领取凭证，必须作为敏感凭证现场出示，不转发。

只用站内 JS 在本机生成 SVG，不调用第三方二维码图片服务，不把凭证写入 URL、localStorage、Service Worker 缓存或扫码审计日志。数据库仍仅存本人码 SHA-256 摘要；刷新失效、到期及一次性消费以服务器为准，修改客户端显示或二维码不能延长有效期。倒计时是展示，不替代服务器验证。

黑白码保留四模块静区，使用 M 纠错，不嵌入徽标或动态图形。库为 [qrcode-generator 2.0.4](https://github.com/kazuhikoarase/qrcode-generator)，固定上游 `83b7e8fe3fddd3b0368dbafd6ce56995bd25e3c8/js/dist/qrcode.js`；MIT 许可保留于 `assets/js/qrcode-generator-LICENSE.txt`。依据[上游 API](https://github.com/kazuhikoarase/qrcode-generator/blob/83b7e8fe3fddd3b0368dbafd6ce56995bd25e3c8/js/README.md)使用 Alphanumeric 编码和本地矩阵渲染。

二维码不能自动证明自然人身份，也不能阻止有效期内的实时转发、屏幕共享或串通；现场人员核验仍必须执行。生成二维码不核销、不重复抽奖、不消耗额外库存。
