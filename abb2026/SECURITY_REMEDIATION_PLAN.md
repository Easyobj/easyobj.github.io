## 边界与发布要求

- 每阶段：实现 → 临时数据库与移动端回归 → 扫描凭据 → 同步源码 main 和 Pages master → 等待线上版本标识 → 交付两个提交哈希和 URL。任一门禁失败不得声明阶段完成。
- 本地测试库与正式奖池隔离，不用真实用户、真实奖品或公众号接口做攻击/压力测试。
- Pages 仅视觉预览，PHP 修复需在正式服务器部署才能生效；不把预览发布当作生产上线。
- 不自动轮换旧账号/密钥、不调整去年数据库权限、不改变活动起止时间、库存、概率或官方渠道地址。

## 阶段 1：后台认证与会话基线（V5.9.0，已发布）

风险：用户名的数据库排序规则与限速键不一致；按 IP+用户名计数可被换 IP 绕过；计数非原子；后台无应用层会话过期。

实施：

1. 后台仅接受创建工具允许的 ASCII 用户名，统一小写查询；拒绝重音、数组和超长输入。
2. 已存在账号按数据库管理员 ID 聚合限速，独立 IP 桶限制所有登录请求，包括无效用户名。
3. 新建 security_rate_limits 表，原子计数、固定窗口、过期清理工具；不清空旧业务表。
4. 默认账号每 15 分钟最多 5 次登录尝试、IP 每 15 分钟最多 50 次。成功登录重置账号桶但不清除 IP 桶；这些默认值可根据现场实际调整。
5. 会话默认 15 分钟空闲超时、8 小时绝对超时；重新登录/退出旋转 Session ID 与 CSRF，账号停用立即失效。
6. 会话绑定密码哈希指纹，CLI 重置密码后旧后台会话失效；日志不得输出原始 PDO/微信异常消息。

验证：重音用户名不再映射登录；换 IP 仍共享账号限制；大小写一致；并发计数不丢失；锁定窗口恢复；正确密码、登录/退出、超时、密码重置、CSRF 旋转；原有 63 项业务检查与 375/390px 移动端回归。

回滚：新表为增量创建，旧代码可忽略；代码回滚不删除新表、不恢复旧明文凭据。后台用户需重新登录。

## 阶段 2：业务限频与资源保护（V5.9.1）

- 将同一原子限频服务接入答题、抽奖、OAuth 与后台敏感动作；按用户/动作计数，不仅按浏览器 Session。
- 答题默认每账号每分钟 12 次、抽奖每分钟 3 次（已中奖结果查询不再次扣奖）；异常返回可理解的冷却提示。
- 限制请求体及 JSON/字段类型、拒绝嵌套数组和超长输入；已通过站点不得因重复提交不断写 attempts。
- 健康检查详细数据库报告改为运维受控访问；公开存活检查轻量化，避免匿名请求不断查库。
- 提供 Nginx limit_req/limit_conn 与受信代理真实 IP 配置。展会出口 IP 仅辅助，不用一 IP 一奖规则误伤共享网络。
- 验证窗口、跨 Session 同用户、并发、代理伪造、拒绝请求不写答案/扣库存，以及正常六站流程。

## 阶段 3：答题自动化与重放防护（V5.9.2）

- 正式判题只由服务端执行；移除生产脚本的正确答案。Pages 静态验收不携带业务 PHP 配置/运行缓存，服务器源码公开仍可能暴露题库，不能靠隐藏答案单独防刷。
- 为表单发放绑定用户、站点/动作、期限的随机挑战；服务端验签/消费，防过期和重复提交。多标签页与网络重试应有清晰恢复路径。
- 异常快速通关、集中多账号使用只作为风险信号；不通过前端计时或设备指纹决定身份。
- 验证篡改/过期/跨用户/跨动作/重放、浏览器后退与多标签；保留已有答题记录与视觉反馈。
- 不擅自提高开放题字数或增加关键词门槛；这属于活动规则。验证码供应商需活动方批准和真实配置，未接入前不得假装通过。

## 阶段 4：核销权限与风控运营（V5.9.3）

- 管理员区分运营管理与仅核销角色；CLI 明确创建/更新角色，原管理员默认保留原权限避免误锁。
- 核销人员不能改库存、概率或导出用户答案；敏感调整审计，异常库存/发奖速度告警。
- 增加暂停新抽奖开关，保留既有结果查询和核销；风险用户审核/解除操作留痕。
- 若活动规则要求本人领取，增加服务器签发的短期兑奖确认流程；静态截图不作为独立发奖依据。
- 验证越权、重复核销、暂停期间库存、审计完整性与移动端后台。

## 阶段 5：工作人员现场核验与本人领取（V5.9.4）

用户已确认：核验由现场工作人员进行，必须本人领取，领奖前核验；正式部署暂不考虑。程序不自行定义适用人员或接入虚构主办方名单，资格由工作人员按实际现场规则判断。不引入未经批准的电子参会凭证、手机号、身份证采集或自然人身份唯一标识。

实施顺序与当前内容：

1. 活动说明及兑奖页面明确本人现场领取、工作人员核验资格、不接受截图或代领；保留 PHP 模板和普通 POST。操作说明见 `ONSITE_REDEMPTION.md`。
2. 新增 `claim_confirmations` 增量表，不改已有答题、中奖、库存或账号。参与者在自己的已授权微信会话中生成绑定中奖账号和奖品的 16 位随机领取确认码，两分钟有效、每用户每分钟最多三次，数据库仅存 SHA-256。新码替换旧码，每页新增一个领取操作表单凭证。
3. 工作人员查询待核销记录必须同时输入兑奖码和当前本人确认码；已核销状态查询无需新码且不提供再次发奖按钮。工作人员短期确认绑定管理员、奖品、风险审核版本和本人码摘要，不延长本人码期限。
4. 必须明确勾选“现场资格已核验”和“本人持自己的微信页面领取”后，服务端再次复核本人码、人员权限、风险审核版本和未核销状态。查询采用一致事务锁，防止并发核销使状态与本人码读取互相矛盾。
5. 核销在同一事务原子消费本人码、写入核销状态及审计；审计失败整笔回滚。过期、更新、跨账号/奖品、重复提交、账号停用或角色失效均不可授权新核销。原有一账号一抽奖、一中奖记录一核销约束保持。
6. 未通过核验只允许“资格尚未核实”或“不是本人领取”固定结论留痕，不记录额外身份资料、不核销、不取消中奖、不释放库存。后续补验重新查询。人工风险解除与资格确认是不同操作，不互相替代。
7. 隔离测试覆盖生成/更新/过期、跨账号/奖品、表单及确认码重放、缺少确认、核验拒绝、账号/权限失效、并发核销、审计失败回滚及正常移动流程；通过发布门禁后以交付记录提供提交哈希与 URL，不把 Pages 发布等同于正式微信业务上线。

保留边界：工作人员确认与短期码均不能自动证明自然人身份。无唯一参会标识，不宣称严格实现自然人“一人一次”；领奖前核验不能阻止多账号先抽奖占库存，短期码也不能阻止实时转发或串通。过期码摘要由已有受控安全清理脚本限量删除，既有业务和审计保留策略不变；日后正式上线再确认运营审计期限。如需电子资格/自然人唯一去重或未领取奖品回收，须另行明确规则，不能擅自添加。
